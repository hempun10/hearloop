hearloop is a public feedback board with a build loop attached. Your users post requests and vote. Your team approves the ones worth building and hands each one to a teammate or a coding agent. The agent builds it in your repository, Kane CLI tests it in a real browser, and only a passing test moves it to **Shipped**.

## Features

- **A public board.** People post requests, vote once each, and comment. Each board has a roadmap and a changelog.
- **Approval first.** New requests stay **Open** until a member moves them to **Planned**. Agents can't touch anything you haven't approved.
- **Agents as teammates.** Claude Code, GitHub Copilot, Codex, Cursor and Pi connect over MCP. Each one shows up on your board, so you can assign it work.
- **Proof before shipping.** Kane CLI runs a plain-English test against your app. A pass ships the request and publishes the changelog entry. A fail sends it back with the report.
- **Your own workflow.** Add boards to group requests, your own statuses, and tags.
- **Your team stays in the loop.** Slack and Discord get the events you pick.

## How one request moves

1. A user posts a request, and other users vote on it.
2. A member moves it from **Open** to **Planned** and assigns it.
3. The agent claims it. The board shows it **In progress**, with the agent's name.
4. The agent changes your code, and Kane CLI tests the change in a browser.
5. A pass ships the request. A fail sends it back to **Planned** with Kane's report.
