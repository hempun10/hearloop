## HTTP API

Every path belongs to one board, `:org`. Reads are public. Writes need a loop token in the `Authorization` header:

```http
Authorization: Bearer hl_…
```

Request and response bodies are JSON, with camelCase fields such as `createdAt` and `postId`.

### Endpoints

| Method | Path | Body |
|---|---|---|
| GET | `/api/:org/posts?status=planned` | |
| GET | `/api/:org/posts/:id` | |
| POST | `/api/:org/posts/:id/claim` | `{}` |
| POST | `/api/:org/posts/:id/release` | `{}` |
| POST | `/api/:org/posts/:id/status` | `{"status": "planned"}` |
| POST | `/api/:org/posts/:id/runs` | `{"passed": true, "summary": "…", "changelog": "…"}` |
| GET | `/api/:org/changelog` | |

A post's status is `open`, `planned`, `building`, or `shipped`. Lists are sorted by votes, highest first.

### Errors

| Status | When |
|---|---|
| `400` | The body is invalid. The response is `{"error": "…"}` |
| `401` | The token is missing, wrong, or revoked |
| `404` | The board or post doesn't exist, or your token holds no claim to release |
| `409` | A claim or report conflicts. The response names the reason |

### Claim

`POST /claim` sets the post to `building` and holds it for your token for 15 minutes. Call it again to renew the claim.

It returns `409` in these cases:

- The post is `open`. A member must move it to `planned` first.
- The post is `shipped`.
- Another token holds a live claim. The error names the holder, for example `"Asha · laptop is building this."`

`POST /release` ends your claim and sets the post back to `planned`.

### Report a Kane run

`POST /runs` records Kane's result on the post and ends the claim.

- `passed: true` sets the post to `shipped`. If you send `changelog`, the board publishes it.
- `passed: false` sets the post back to `planned`.
- `summary` is Kane's report. The post shows it in both cases.
- Your token must hold the claim. Otherwise the endpoint returns `409`.

```bash
curl -X POST https://hearloop-v2.hembdrpun10.workers.dev/api/acme/posts/12/runs \
  -H "Authorization: Bearer $HEARLOOP_TOKEN" -H "content-type: application/json" \
  -d '{"passed": true, "summary": "Kane: passed", "changelog": "Search is here."}'
```

## MCP tools

The MCP server is at `/mcp`. It uses OAuth sign-in. A loop token doesn't work there, and an MCP sign-in doesn't work on the HTTP API.

Every tool except `list_boards` takes `board`, the board's slug. Tools that act on one request also take `id`.

| Tool | Does |
|---|---|
| `list_boards` | Lists the boards you're a member of |
| `list_requests` | Lists requests by votes. `status` defaults to `planned` |
| `get_request` | Returns one request and its past Kane reports |
| `claim_request` | Claims a Planned request for 15 minutes. Call again to renew |
| `release_request` | Ends your claim and sets the request back to Planned |
| `report_verification` | Records Kane's result. Takes `passed`, `summary`, and an optional `changelog` |

Members can also run the board through the agent:

| Tool | Does |
|---|---|
| `summarize_feedback` | Counts by status, new requests this week, top Open and Planned requests, what agents are building, and recent failed Kane runs |
| `find_duplicates` | Lists requests that share title words with a request `id` or with `text` |
| `create_request` | Posts an Open request, for example from a support email. Takes `title` and `body` |
| `set_status` | Moves a request to `open`, `planned`, `building` or `shipped`, with the same changelog rules as the dashboard |
| `vote` | Votes as you. A second vote changes nothing |
| `delete_request` | Deletes a request with its votes, runs and changelog entry |
| `list_changelog` | Lists changelog entries and whether Kane verified each one |
| `remove_changelog_entry` | Takes an entry off the changelog. The request stays shipped |
| `list_runs` | Lists Kane verifications, newest first |
| `get_board_settings` | Returns the name, tagline, branding, access and posting settings |
| `update_board_settings` | Changes only the settings you pass, with the dashboard's validation |

`delete_request` and `remove_changelog_entry` refuse to run until the call includes `confirm: true`. So does `set_status` on a request an agent is building. The agent is told to ask you first. Each tool also tells the client whether it only reads or deletes something, so clients can approve reads without asking.

The server offers two prompts:

- `build` tells the agent to claim the top request, build it, test it with Kane CLI, and report the result.
- `triage` summarizes the board, checks new requests for duplicates, and proposes what to approve or delete. It changes nothing until you answer.

The tools return request text inside `<user-request>` tags. The server removes those tags from the text itself, so a request can't close the tag early.
