---
title: Verify a change in CI
description: Run only the Kane check and report the result, from CI or for code you wrote yourself.
---

`hearloop verify` skips the agent and the build. It runs one Kane test against the `app` URL in `hearloop.json` and reports the result on the request.

## Verify from your terminal

Run:

```bash
HEARLOOP_TOKEN=hl_… npx hearloop verify 12 "Go to the board. Click 'Dark mode'. Verify the page turns dark."
```

If you leave out the objective, the CLI reads it from `.hearloop/kane-objective.txt`. If `.hearloop/changelog.md` exists, the CLI publishes it when the test passes.

The command claims the request first, so the request must be **Planned** or already claimed by your token. The command exits with `0` on a pass and `1` on a fail.

## Verify in GitHub Actions

1. In your repository settings, add the loop token as the secret `HEARLOOP_TOKEN`.
2. Add the variables `HEARLOOP_POST` and `HEARLOOP_OBJECTIVE`.
3. Add this workflow:

```yaml title=".github/workflows/hearloop.yml"
on:
  pull_request:
jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm i -g @testmuai/kane-cli
      # deploy a preview here and point "app" in hearloop.json at it
      - run: npx hearloop verify ${{ vars.HEARLOOP_POST }} "${{ vars.HEARLOOP_OBJECTIVE }}"
        env:
          HEARLOOP_TOKEN: ${{ secrets.HEARLOOP_TOKEN }}
```

Kane must also be signed in on the runner. For CI sign-in, see the [Kane CLI documentation](https://github.com/LambdaTest/kane-cli).
