---
title: Choose a coding agent
description: Use a supported agent, your own command, or write the code yourself.
---

Set the `agent` field in `hearloop.json`. The agent must be installed and signed in on the machine that runs the loop.

## Use a supported agent

| `agent` | Command the CLI runs |
|---|---|
| `claude` | `claude -p <prompt> --permission-mode acceptEdits` |
| `codex` | `codex exec --sandbox workspace-write <prompt>` |
| `cursor` | `cursor-agent -p <prompt> --force` |
| `gemini` | `gemini -p <prompt> --approval-mode auto_edit` |
| `aider` | `aider --yes-always --message <prompt>` |
| `manual` | Nothing. You [write the code yourself](#write-the-code-yourself) |

Every agent gets the same prompt. The prompt contains the request, Kane's last failure report if there is one, and an instruction to follow your repository's README, AGENTS.md, and CLAUDE.md. It also asks the agent to write the Kane test to `.hearloop/kane-objective.txt`.

## Use your own command

Write any shell command that contains `{prompt}`:

```json
{ "agent": "my-agent run --task {prompt} --yes" }
```

The CLI replaces `{prompt}` with the quoted variable `"$HEARLOOP_PROMPT"`. Quotes inside a request therefore can't break your command.

## Write the code yourself

Set `agent` to `manual`:

```json
{ "agent": "manual" }
```

`hearloop run` prints the request, saves it to `.hearloop/prompt.md`, and waits.

1. Write the code.
2. Press **Enter**.
3. Type what Kane should check, as one plain-English browser test. To skip this question, write the test to `.hearloop/kane-objective.txt` before you press **Enter**.

Kane tests your app, and the board updates the same way it does for an agent.

If the code already exists, for example in a pull request, use [`hearloop verify`](/docs/ci) instead.
