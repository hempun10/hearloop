# hearloop

**Feedback that ships itself.** A public feedback board where coding agents build what customers ask for, and nothing ships until Kane CLI proves it works in a real browser.

[hearloop.app](https://hearloop.app) · [Docs](https://hearloop-docs.hembdrpun10.workers.dev/docs) · Built for the KaneCLI Online Hackathon (November 2026)

## Demo

▶ **[Watch the 2-minute demo](demo/hearloop-demo.mp4)**: a real feature, the embeddable widget, going from a customer's request to a verified release.

## How it works

1. Customers post ideas on a public board and vote on them.
2. The team hears about new requests in Slack or Discord.
3. A teammate approves a request and assigns it to a coding agent: Claude Code, Codex, Cursor, OpenCode or any MCP client.
4. The agent claims the request over MCP, builds it, and asks Kane CLI to test it in a real browser from a plain-English description.
5. A pass moves the request to **Shipped** and publishes a changelog entry marked *Verified with Kane CLI*. A fail sends it back to **Planned** with Kane's report, and the agent tries again.

Nothing reaches the changelog without a passing Kane run.

Boards also come with a roadmap, a changelog, custom statuses, categories and tags, team invites, and an embeddable widget: one script tag puts the board on any site.

## Run locally

```bash
bun install
cp apps/web/.dev.vars.example apps/web/.dev.vars   # set BETTER_AUTH_SECRET (openssl rand -hex 32)
bun run db:migrate
bun run dev                      # web http://localhost:3000, docs http://localhost:3001
```

Sign up and name your board (it lives at `/<your-org>`).
Boards are public to read, post and vote; only members see Settings.

## Build requests with your coding agent

Connect Claude Code, Cursor or any MCP client to the board's MCP server (`/mcp`). It signs in through your browser, so there's no token to copy:

```bash
claude mcp add --transport http --scope user hearloop http://localhost:3000/mcp
```

A repo's `hearloop.json` names its board and app URL (`apps/web/hearloop.json` locally, `hearloop.prod.json` live). Run `/mcp__hearloop__build` and the agent claims the top Planned request, builds it, verifies it with Kane CLI and reports the result.

Kane CLI needs a Chromium. If Chrome isn't installed, set `KANE_CLI_CHROME_PATH`.

## Kane test suite

Tests live in `apps/web/kane/<area>/*_test.md`, one folder per Test Manager folder (see `apps/web/kane/suite.ts`):
01 Smoke, 02 Auth, 03 Orgs & onboarding, 04 Public board, 05 Roadmap & changelog, 06 Dashboard, 07 Branding & access, 08 Loop verifications.

```bash
bun run e2e:seed            # reset the fixture: e2e@hearloop.test owning /acme (password in .testmuai/variables/e2e.json)
bun run kane run smoke      # replay one area (cheap, uses the recorded steps)
bun run kane run all
bun run kane record <area>  # record tests added to kane/suite.ts, filed into that area's folder
```

Every objective starts at `{{base_url}}`, so the same recordings run against any deployment.

## Deploy your own

hearloop runs on Cloudflare Workers with D1. `apps/web/wrangler.jsonc` is set up for hearloop.app, so change two things first:

- Replace `database_id` with the id that `wrangler d1 create` prints.
- Remove the `routes` entry, or point it at your own domain.

```bash
cd apps/web
bunx wrangler d1 create hearloop-v2
bun run db:migrate:remote
cd ../.. && bun run deploy:web && bun run deploy:docs
bunx wrangler secret put BETTER_AUTH_SECRET    # and set BETTER_AUTH_URL in wrangler.jsonc vars
```

## Agent API

Every path is scoped to an org. Reads are public. Writes need `Authorization: Bearer <org token>`. Bodies are validated with zod; a bad body gets `400 {"error": …}`. Responses use camelCase fields (`createdAt`, `postId`).

| Method | Path | Body |
|---|---|---|
| GET | `/api/:org/posts?status=open` | |
| GET | `/api/:org/posts/:id` | |
| POST | `/api/:org/posts/:id/status` | `{"status":"building"}` |
| POST | `/api/:org/posts/:id/runs` | `{"passed":true,"summary":"…","changelog":"…"}` |
| GET | `/api/:org/changelog` | |

## Stack

- **App:** TanStack Start (React 19, SSR) on Cloudflare Workers
- **Data:** D1 through Drizzle ORM (`apps/web/src/db/schema.ts`); migrations generated by drizzle-kit, applied by wrangler
- **Auth:** Better Auth (email and password), with auth checks as TanStack Start function middleware
- **Client data:** TanStack Query, with router SSR integration
- **UI:** shadcn/ui (Radix), Tailwind v4, lucide icons, sonner toasts, @dnd-kit for the roadmap
- **Forms:** react-hook-form + zod; the same schemas validate the server functions
- **Docs:** Fumadocs (`apps/docs`)
- **Monorepo:** Bun workspaces, Turborepo, shared `@hearloop/ui` and `@hearloop/typescript-config`
- **Tests:** Kane CLI (`apps/web/kane/`)
